# Configuración incorrecta de disparadores de Defer

Este diagnóstico detecta disparadores inalcanzables o redundantes en bloques `@defer`.

```typescript

import {Component} from '@angular/core';

@Component({
  template: `
    @defer (on immediate; on timer(500ms)) {
      <large-component />
    }
  `
})
class MyComponent {}
```

## ¿Qué está mal con eso? {#whats-wrong-with-that}

El diagnóstico identifica varios patrones problemáticos en la configuración de disparadores de defer que conducen a:

- **Código innecesario** que nunca afecta el comportamiento
- **Oportunidades de optimización perdidas** para un mejor rendimiento
- **Disparadores de precarga inalcanzables** que nunca se ejecutarán

## Casos de advertencia del diagnóstico {#diagnostic-warning-cases}

Este diagnóstico marca los siguientes patrones problemáticos:

### `immediate` con disparadores de precarga {#immediate-with-prefetch-triggers}

**Incorrecto — la precarga nunca se ejecuta**

```typescript
@Component({
  template: `
    @defer (on immediate; prefetch on idle) {
      <my-cmp />
    }
  `
})
class MyComponent {}
```

**Correcto — elimina la precarga redundante**

```typescript
@Component({
  template: `
    @defer (on immediate) {
      <my-cmp />
    }
  `
})
class MyComponent {}
```

### Temporizador de precarga no anterior al temporizador principal {#prefetch-timer-not-earlier-than-main-timer}

**Incorrecto — la precarga es posterior al principal**

```typescript
@Component({
  template: `
    @defer (on timer(100ms); prefetch on timer(3000ms)) {
      <my-cmp />
    }
  `
})
class MyComponent {}
```

**Incorrecto — el mismo tiempo no aporta ningún beneficio**

```typescript
@Component({
  template: `
    @defer (on timer(500ms); prefetch on timer(500ms)) {
      <my-cmp />
    }
  `
})
class MyComponent {}
```

**Correcto — la precarga se dispara antes**

```typescript
@Component({
  template: `
    @defer (on timer(1000ms); prefetch on timer(500ms)) {
      <large-component />
    }
  `
})
class MyComponent {}
```

### Precarga sin disparadores principales {#prefetch-without-main-triggers}

```angular-ts {avoid, header: "obtención anticipada inesperada"}
@Component({
  template: `
    @defer (prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

Esta configuración puede sugerir que la precarga solo se ejecutará cuando `someFlag` se vuelva verdadero. Sin embargo, dado que el disparador principal sigue siendo por defecto `on idle`, el contenido diferido puede obtenerse antes durante el período de inactividad del navegador, omitiendo efectivamente la condición prevista.

```angular-ts {prefer, header: "definir explícitamente el disparador principal"}
@Component({
  template: `
    @defer (on interaction; prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

### Disparadores de precarga y principal idénticos {#identical-prefetch-and-main-triggers}

**Incorrecto — disparador de viewport idéntico**

```typescript
@Component({
  template: `
    @defer (on viewport; prefetch on viewport) {
      <my-cmp />
    }
  `
})
class MyComponent {}
```

**Incorrecto — objetivo de interacción idéntico**

```typescript
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn); prefetch on interaction(loadBtn)) {
      <large-component />
    }
  `
})
class MyComponent {}
```

**Correcto — elimina la precarga redundante**

```typescript
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn)) {
      <large-component />
    }
  `
})
class MyComponent {}
```

**Correcto — usa objetivos diferentes para la precarga y el principal**

```typescript
@Component({
  template: `
    <div #hoverArea>Hover to prefetch</div>
    <button #clickBtn>Click to load</button>
    @defer (on interaction(clickBtn); prefetch on hover(hoverArea)) {
      <large-component />
    }
  `
})
class MyComponent {}
```

## Requisitos de configuración {#configuration-requirements}

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) debe estar habilitado para que se emita cualquier diagnóstico extendido.
`deferTriggerMisconfiguration` no tiene requisitos adicionales más allá de `strictTemplates`.

## ¿Qué pasa si no puedo evitar esto? {#what-if-i-cant-avoid-this}

Este diagnóstico puede deshabilitarse editando el archivo `tsconfig.json` del proyecto:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "deferTriggerMisconfiguration": "suppress"
      }
    }
  }
}
```

Consulta la [configuración de diagnósticos extendidos](extended-diagnostics#configuración) para más información.
